## Данные и погода

### Источники
| Что | Откуда |
|---|---|
| Мощность, ветер, температура турбин (10 мин, 11.03.2023–31.01.2026) | CSV организаторов, `data/raw/` |
| Архивные прогнозы погоды | [Open-Meteo Previous Runs API](https://open-meteo.com/en/docs/previous-runs-api), модели ECMWF IFS 0.25° (`ecmwf_ifs025`) и GFS (`gfs_seamless`), без ключа, лицензия CC BY 4.0 |

Координаты: турбина 1 — 43.645150, 78.535604 (Алматинская обл.). Погода берётся в одной точке: турбины стоят рядом, а сетка моделей 9–25 км.

Переменные прогноза: ветер на 10 и 100 м, направление на 100 м, порывы на 10 м, температура на 2 м.

### Как исключена утечка будущего
Используются только **прогнозы**, фактическая погода не используется. Previous Runs API хранит для каждого часа значение, предсказанное моделью за N суток до него (`<var>_previous_dayN`).

Прогноз выпускается в момент T (по умолчанию 00:00 UTC). Для цели с лидом L часов берётся `previous_dayN`, где

`N = ceil((L + 8) / 24)`, 8 ч — консервативная задержка публикации прогона.

| Лид, ч | Источник | Прогон стартовал не позже |
|---|---|---|
| 1–16 | `previous_day1` | T − 8 ч |
| 17–40 | `previous_day2` | T − 8 ч |
| 41–48 | `previous_day3` | T − 8 ч |

То есть каждый использованный прогон был опубликован до момента выпуска прогноза. Функция `check_no_leakage()` проверяет это правило для каждой строки train и test и падает, если оно нарушено.

Train и test собираются одной функцией `assemble()` по одному правилу. Поэтому ошибки погодного прогноза в обучении такие же, как в феврале.

### Время
«Статистическое время» SCADA — это **UTC+6**, старое время Алматы. В марте 2024 Казахстан перешёл на UTC+5, но в данных нет ни дубля, ни разрыва на 01.03.2024: часы SCADA не переводили.

Сдвиг определяется автоматически по корреляции скорости ветра SCADA с прогнозом NWP на 100 м при сдвигах от +3 до +9 ч, максимум приходится на +6. Температуру для этого не используем: её датчик стоит на гондоле, на высоте около 100 м. Там суточный ход отстаёт от прогноза на 2 м, и по температуре сдвиг выходит на час больше. Результат сохраняется в `data/processed/meta.json`.

Внутри пайплайна всё хранится в UTC; `target_time_local` — то же время по часам SCADA.

Целевой час — интервал `[target_time, target_time + 1 ч)`:
- мощность — среднее 10-минутных значений за этот час (нужно не меньше 4 из 6 записей);
- погодные признаки — среднее мгновенных значений прогноза на границах часа.

### Очистка SCADA
- Мощность станции `power` — среднее по турбинам, у которых есть данные за час. Если у одной турбины пропуск (например, 41 день летом 2024 у турбины 1), берётся вторая.
- `is_anomaly` — простои и ограничения мощности (curtailment): при ветре ≥ 4,5 м/с мощность ниже эмпирической кривой мощности больше чем наполовину. Таких часов около 1–2%.
- `power_clean` — мощность без аномальных часов. Для обучения лучше брать её.

### Запуск
```bash
pip install -r requirements.txt
# положить два CSV организаторов в data/raw/
python -m data.build_dataset          # около 5 минут, ответы API кэшируются в data/cache/
```

Результат в `data/processed/`:
- `train.parquet` — строка = (выпуск, лид): погодные признаки + фактическая мощность, 2024-01 … 2026-01;
- `test_features.parquet` — выпуски 31.01–28.02.2026, только признаки;
- `scada_hourly.parquet` — почасовая SCADA станции, для бейзлайнов;
- `meta.json` — сдвиг времени, модели, список признаков.

### Интерфейс для агента
```python
from data.weather_client import fetch_forecast
from data.features import add_features

wx = fetch_forecast("2026-02-10T00:00")   # 48 строк, погода, известная на 00:00 UTC
X = add_features(wx)                       # те же признаки, что в train
```

Признаки (`features.feature_columns`):
- по каждой модели: ветер, направление (sin/cos), порывы, температура, сдвиг ветра по высоте, удельная мощность ветра с поправкой на плотность воздуха;
- по ансамблю моделей: среднее и разброс скорости ветра между ECMWF и GFS (мера неопределённости);
- календарные: час, сезон, лид, `day_offset`.

### Ограничения и развитие
- Previous Runs API хранит архив с января 2024, поэтому 2023 год в обучение не попадает. Историю можно достроить через Historical Forecast API, но там короткие лиды, то есть другой профиль ошибок.
- `previous_dayN` даёт лид, кратный суткам. Точный прогон по времени старта можно получать через Open-Meteo Single Runs API (ECMWF IFS HRES с марта 2024). Это следующий шаг для «повторного расчёта» на прогонах 00/06/12/18 UTC.
- Можно добавить модели ICON, JMA и GEM: в `config.MODELS` это одна строка на модель.
