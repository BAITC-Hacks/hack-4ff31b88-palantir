# Агент данных Palantir

## Что делает

Отдельная страница `app/repository_agent.py` показывает сохранённые результаты
проекта. График и таблицы читают числа прямо из файлов. Чат использует OpenAI
Responses API: модель выбирает инструмент, Python читает нужные данные,
результат передаётся модели, затем она формирует ответ на русском. В ответе
видны реально прочитанные файлы и выполненные обращения к инструментам.

Это агент анализа сохранённых результатов. Численный прогноз мощности
рассчитывает существующая модель проекта; новый чат не обучает её и не запускает
бэктест. Страница `app/dashboard.py` продолжает работать отдельно.

## Запуск

Из корня проекта в PowerShell:

```powershell
py -m pip install -r requirements-agent.txt
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'API-ключ OpenAI' -AsSecureString)).Password
py -m streamlit run app/repository_agent.py --server.address 127.0.0.1 --server.port 8502
```

Страница: http://localhost:8502. Если ключ уже задан в этом терминале, повторный
ввод не нужен. После задания ключа перезапустите ранее запущенный Streamlit.
Ключ не нужно добавлять в исходный код, GitHub или чат. `.env` автоматически
не загружается; используется переменная окружения `OPENAI_API_KEY`.

По умолчанию выбрана `gpt-5.4-mini`. Для другой доступной модели задайте
`$env:OPENAI_MODEL = 'имя-модели'` или измените поле на странице.

Один вопрос из терминала:

```powershell
py repository_agent.py "Подведи итоги бэктеста" --run artifacts/agent_lgbm_llm
```

## Источники

Прогоны обнаруживаются в `artifacts/` и `outputs/` по `summary.json`.
Страница начинает с `artifacts/agent_lgbm_llm`, если он существует.

| Инструмент | Данные |
|---|---|
| `get_run_summary` | `summary.json` выбранного прогона и сводные счётчики из `runs.jsonl` |
| `get_forecast` | `february_latest.csv`; для конкретного выпуска — принятые строки `forecast_history.csv` |
| `get_checks` | `runs.jsonl`: решения, ошибки, предупреждения, изменения версий |
| `get_metrics` | `model/metrics_baseline.csv`, `metrics_lgbm.csv`, `metrics_february.csv` |

Это файлы локальной копии проекта. После обновления файлов нажмите «Обновить
данные». Кнопка перечитывает файлы; синхронизация GitHub выполняется обычным
`git pull` в вашем репозитории. Чат не получает доступ к произвольным файлам,
секретам, GitHub-токенам, shell или записи на диск.

## Как читать результаты

- `power_pred` — доля установленной мощности. На графике она переведена в проценты.
- `target_time` и `issue_time` — UTC. Даты для фильтра графика и запросы вида
  «10 февраля» относятся к местному календарю SCADA (в текущем наборе UTC+6).
- `accepted=true` означает прохождение проверок; это не оценка точности прогноза.
- `errors=[]` означает отсутствие ошибок валидации, а не нулевую ошибку мощности.
- Изменения сравниваются по перекрывающимся часам. Первый выпуск не имеет
  предыдущей версии для сравнения.
- Метрики января — валидация. Февраль с `n=0`/пустой метрикой означает, что
  фактических наблюдений для оценки нет.
- Фильтр графика действует на отображаемую таблицу. Чату указывайте нужные даты
  в вопросе; он может анализировать весь выбранный прогон.

## Ограничения запросов

Открытие страницы, выбор прогона и просмотр графиков не вызывают OpenAI.
На один отправленный вопрос разрешено до 5 обращений к API и до 8 чтений
инструментов. Один ответ ограничен 1800 выходными токенами на обращение,
время ожидания каждого обращения — 45 секунд, автоматических повторов нет.
Фактический расход зависит от вопроса и выбранной модели.

В инструментах ограничивается объём подробных строк, но статистика прогноза
считается по всему выбранному периоду. Сокращение данных явно помечается.
Пустой или незавершённый ответ и ошибки API отображаются как ошибка запроса;
ответ по правилам не выдаётся за ответ OpenAI. История диалога хранится в сессии
страницы, отдельно для каждого прогона и модели. При следующем вопросе
передаётся не более шести последних сообщений.

## Проверка

```powershell
py -m unittest discover -s tests -v
```

Тесты чтения проверяют даты, единицы, полноту выборки, выбор принятой версии,
пустые метрики и ограничения доступа. Тесты агента подменяют ответы API и
проверяют цикл инструментов, обработку сбоев, лимиты и источники. Эти тесты
не расходуют API-баланс и не заменяют проверку живого запроса с вашим ключом.

В интерфейсе первый успешный ответ с источниками подтверждает работу нового
агента с API. Надпись «Ключ API задан» проверяет только наличие переменной.

Реализация использует [официальную документацию OpenAI по function calling](https://developers.openai.com/api/docs/guides/function-calling).
