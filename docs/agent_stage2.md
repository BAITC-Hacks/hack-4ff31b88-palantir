# Человек 3: анализ и ежедневный бэктест

Реализован следующий этап поверх `agent_skeleton.py`: проверки прогноза,
резюме и виртуальные часы. Погода и модель **пока заглушки**; постоянный прогноз
0.5 не является результатом модели ВЭС. Весь эксперимент помечен `mode=stub`.
Файлы `data/`, `model/`, общий README и requirements.txt не изменяются.

## Запуск

Из корня репозитория, Python 3.10+, без дополнительных зависимостей:

```bash
python agent_skeleton.py --issue-time 2026-01-31T00:00:00+00:00 --output artifacts/single.json
python agent_backtest.py --out artifacts/backtest_01
python -m unittest discover -s tests -p test_agent_stage2.py -v
```

Для каждого нового эксперимента указывай новую папку `--out`. Существующая база
не перезаписывается. Возобновление прерванного эксперимента пока не реализовано.
Сама база сохраняет уже завершённые дни; CSV/JSONL экспортируются в конце запуска.

## Календарь

Настройки берутся из существующего `data.config` и `data/processed/meta.json`:

- выпуски 31.01–28.02.2026 включительно, 00:00 UTC, 29 запусков;
- горизонт 48 часов, первый интервал начинается в момент выпуска;
- SCADA сейчас UTC+6; февраль отбирается по часам SCADA;
- `lead_hour=1` означает интервал `[issue_time, issue_time+1h)`.

Итог за февраль — 672 часа станции. В истории также остаются январские и мартовские
часы. Naive-время принимается как UTC согласно контракту модуля данных.
Аргументы `--start`/`--end` позволяют проверять короткий фрагмент, но полнота
в отчёте всё равно относится ко всему февралю.

## Проверки

- Полнота ожидаемой часовой сетки, отсутствие дублей и лишних часов.
- Мощность 0–1 включительно; 0 не считается пропуском.
- Пропуски, NaN/Inf и значения вне диапазона отклоняют весь пакет.
- Скачок за соседний час больше 0.30 даёт предупреждение.
- Пересмотр старого прогноза того же часа больше 0.15 даёт предупреждение.

Пороги — начальные эвристики в долях нормализованной мощности, не физические
ограничения. Меняются через `--jump`/`--revision`. Значения не обрезаются и не
сглаживаются. Предупреждение не блокирует принятие прогноза.

При успешном ежедневном выпуске заменяются 24 перекрывающихся часа. Журнал хранит
old/new/delta, число изменений, среднюю и максимальную абсолютную разницу.
Даже при совпадении чисел обновляется дата выпуска. Поэтому на постоянной
заглушке будет **672 замены версий (28 × 24), но 0 изменений чисел**.
При отсутствии прошлой версии показатели величины пересмотра равны null.

Ошибка пакета сохраняет прежний прогноз; следующий день всё равно запускается.
Для отклонённого пакета changes описывает предложенные изменения, а replaced_points=0.
Запись дневного отчёта и замены выполняются одной транзакцией SQLite.

## Выходные файлы

- `backtest.sqlite`: история запусков и таблица актуальных значений.
- `runs.jsonl`: один отчёт на виртуальный день с проверками и изменениями.
- `february_latest.csv`: последние принятые версии 672 февральских часов.
- `forecast_history.csv`: численно валидные точки всех пакетов и флаг accepted.
- `summary.json`: даты, покрытие, число принятых выпусков и замен.

Успешный полный прогон возвращает код 0. Ошибка хотя бы одного дня или неполное
покрытие февраля — код 2. Для будущих метрик нужно фильтровать accepted=True,
ограничивать целевые часы февралём и использовать историю по lead_hour.
Отличие от прошлого прогноза не является ошибкой относительно факта.

## Необязательное LLM-резюме

Без ключа работает локальное резюме по правилам. При необходимости отдельно
установи `openai`, задай переменную окружения `OPENAI_API_KEY` и передай
`--llm-model` с доступным именем модели. Например:

```bash
python -m pip install openai
python agent_backtest.py --out artifacts/backtest_llm --llm-model YOUR_MODEL
```

В LLM отправляются только сводные числа, без почасовых рядов и исходных CSV.
Один запрос на день: полный прогон может сделать 29 платных запросов. При ошибке
API, отсутствии SDK или пустом ответе сохраняется локальное резюме.
LLM не меняет прогноз и решение о его принятии.
[Формат Responses API](https://developers.openai.com/api/docs/guides/text).
Реальный внешний LLM-вызов не проверен; тестируются успешный ответ и сбои через заглушку SDK.
