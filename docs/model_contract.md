# Контракт для Человека 2

Нужен импортируемый модуль, например `model.py`, и функция:

```python
def predict(df):
    # df — результат data.features.add_features(), только прогнозные признаки.
    out = df[["target_time"]].copy()
    out["power_pred"] = trained_model.predict(df[feature_names]).clip(0, 1)
    return out
```

Загружай модель один раз, например при импорте. Не обучай её на каждом вызове.
Выход: 48 строк станции, `target_time` без дубликатов, `power_pred` 0–1
(колонка `power` также поддерживается). Это совместимо с `model.baseline_nwp.predict`.
Время без timezone в модуле данных трактуется как UTC согласно его контракту.
Вход уже содержит календарные признаки с тем же сдвигом SCADA, что при обучении.
Не обучай импутер на тестовом феврале.

Добавь `model_metadata.json` с фактической датой доступности всех использованных
данных, включая предобработку и подбор параметров:

```json
{
  "model_name": "lightgbm_station_v1",
  "training_data_available_at": "2026-01-31T17:00:00+00:00"
}
```

Дата — пример, не требование заявлять её без проверки. При текущем сдвиге +7
последний январский час начинается 31.01 16:00 UTC и доступен в 17:00 UTC.
Если есть задержка получения SCADA, учти её. Первый виртуальный выпуск — 31.01 17:00 UTC.
Сдвиг +7 из `meta.json` ещё требует подтверждения команды.

Приложи модель, версию библиотек и добавь зависимости в `requirements.txt`.

```bash
python run_backtest.py --model model:predict --model-metadata model_metadata.json --out runs/model
```

Метрики по горизонтам: `forecast_history.csv`, `accepted=True`, `lead_end_hours`
1–24 / 25–48, только целевые часы февраля по времени SCADA. Нужны факты февраля;
исходные CSV их не содержат.
