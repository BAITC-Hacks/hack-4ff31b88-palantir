# Агент: подключение модулей команды

Из корня репозитория, Python 3.10+:

```bash
pip install -r requirements.txt
python agent_backtest.py --mode baseline --out artifacts/agent_baseline
python -m unittest discover -s tests -v
```

Каждый запуск требует новую выходную папку. Погода скачивается через модуль
`data.weather_client` из main: архив Previous Runs для всего периода, затем
`assemble` и `check_no_leakage` отдельно на каждом виртуальном выпуске.
`data.features.add_features` готовит признаки; `model.baseline_nwp.predict`
или `model.train.predict` добавляет мощность. Проверки и атомарное сохранение
в SQLite выполняет `agent_backtest.py`. Параметр `--mode stub` сохраняет демо.

Календарь берётся из `data.config`: 31.01–28.02.2026 включительно, 00 UTC,
48 часов на выпуск. Февраль в CSV — по времени SCADA UTC+6, 672 часа.
Последующий принятый выпуск заменяет пересечение в 24 часа. Невалидный
выпуск записывается в журнал, предыдущий прогноз сохраняется.

Бейзлайн использует реальные погодные прогнозы и кривую мощности коллеги.
Кривые один раз строятся на train.parquet с ограничением:
конец наблюдаемого часа <= первый issue_time. Это исключает последние
часы января, неизвестные первому выпуску. Готовая power_curve.json на
всей истории намеренно не используется для этого первого выпуска.
В summary.json и каждом выпуске есть режим, граница обучения и SHA256 данных.

## Когда Человек 2 передаст LightGBM

Нужны `model/lightgbm_model.txt`, `model/lightgbm_features.json` и подтверждение
времени доступности последнего наблюдения, использованного в обучении.
Передать это время с часовым поясом через `--trained-through`:

```bash
python agent_backtest.py --mode lightgbm --trained-through <ISO-время-с-часовым-поясом> --out artifacts/agent_lgbm
```

Дата должна быть не позже первого выпуска. Значение сообщает владелец модели;
оно не определяется по времени создания файла. Без файлов или даты запуск
завершается ошибкой, автоматической подмены LightGBM бейзлайном нет.
Порядок признаков проверяется по сохранённой модели. Отсутствующие или
нечисловые используемые признаки отклоняют выпуск.

Для LLM-резюме: дополнительно `pip install openai`, задать OPENAI_API_KEY
в окружении и передать `--llm-model` с доступной моделью. Без него используются
правила; ошибка API также приводит к резюме по правилам.

## Результаты проверки интеграции

19 тестов прошли. Полный прогон бейзлайна на архиве погоды: 29/29 выпусков,
672 часа февраля, 672 заменённых точки, 662 изменения значения.
Проверка выполнена с main 30b764f6 и model-person2 16c7776a.
Архив погоды прочитан из кеша модуля данных; это не тест живого API.

Выход: february_latest.csv, forecast_history.csv, runs.jsonl, summary.json,
backtest.sqlite. Фактической мощности февраля в исходных данных нет:
качество на феврале и график «прогноз против факта» пока не подтверждены.
Запуск с LightGBM ожидает артефакты Человека 2. Код его обучения не менялся.
Правило доступности погоды наследуется из модуля Человека 1; агент проверяет
это правило, но не подтверждает независимо реальные времена публикации NWP.
