# hack-4ff31b88-palantir
Hackathon team repository for Palantir

## Данные и погода

Источники, правило «без утечки будущего», часовой пояс и очистка SCADA описаны в [data/README_data.md](data/README_data.md).
Сборка датасета: `python -m data.build_dataset`.

## Дашборд

```bash
streamlit run app/dashboard.py
```

Откроется в браузере. Вкладки:
- **Прогноз** — почасовая мощность на 48 ч для выбранного выпуска и прогноз ветра ECMWF и GFS;
- **Проверки агента** — диапазон, скачки, расхождение погодных моделей, согласие с прошлым выпуском, журнал агента;
- **Качество модели** — nMAE на январе 2026 и график «факт против прогноза»;
- **Запуск агента** — полный цикл вживую: погода Open-Meteo на момент выпуска → признаки → модель → проверки. Выпуск в 12:00 UTC показывает пересчёт при обновлении прогноза погоды.

## Модель и метрики

Запуск модели: `python -m model.train`. Обучение идёт на `train.parquet` до
01.01.2026, январь 2026 используется для валидации, а февраль — для итогового
прогноза. Используются ветер и его ансамбль, направление в sin/cos,
температура, час, месяц и календарные циклы. Предсказание обрезается в [0, 1].

`nMAE = 100 * mean(abs(y - pred))`; результаты LightGBM записываются в
`model/metrics_lgbm.csv`, прогноз февраля — в `model/forecast_lgbm_feb.csv`.
После появления фактической SCADA скрипт также записывает сравнение LightGBM,
persistence, climatology и power curve за февраль в `model/metrics_february.csv`
с разбиением на горизонты 1–24 и 25–48 часов.

Бейзлайны на январе 2026:

| Модель | 1–24 ч | 25–48 ч | Все горизонты |
|---|---:|---:|---:|
| Persistence | 30.83% | 36.55% | 33.69% |
| Climatology | 29.40% | 29.40% | 29.40% |
| Power curve | 21.35% | 21.53% | 21.44% |

Метрики считаются по фактической мощности `power`, время SCADA — UTC+6
(см. [раздел о данных](data/README_data.md)). Пересчёт: `python -m model.baseline_nwp`.

## Проверка по критериям кейса

Проект покрывает основной сценарий: архивные прогнозы ECMWF/GFS берутся через Open-Meteo Previous Runs API, затем строятся признаки, выполняется прогноз на 48 часов и запускаются проверки диапазона, скачков и расхождения погодных моделей. Доступен последовательный пересчёт для выпусков тестового периода через вкладку «Запуск агента».

Воспроизводимый порядок запуска из корня репозитория:

```powershell
python -m pip install -r requirements.txt
python -m data.build_dataset
python -m model.baseline_nwp
python -m model.train
streamlit run app/dashboard.py
```

Для полного воспроизведения нужны два исходных CSV организаторов в `data/raw/`. Скрипт `data.build_dataset` сохраняет архив погодных ответов в `data/cache/`, собирает `train.parquet`, `test_features.parquet` и `scada_hourly.parquet`. Тестовый период для оценки — целевые часы с 01.02.2026 по 28.02.2026; прогнозы выпусков включают 31.01.2026 и 48-часовой хвост, поэтому при расчёте февральских метрик нужно фильтровать по `target_time_local`.

Ветка `model-person2` содержит актуальное исправление этого фильтра. В `main` оно пока не перенесено. Ветка `codex/agent-backtest` содержит отдельный backtest агента и тесты его этапов.

Ограничения, которые нужно учитывать при оценке: координаты турбины 2 в `data/config.py` пока совпадают с координатами турбины 1; LightGBM-артефакты (`lightgbm_model.txt`, `lightgbm_features.json`, `metrics_lgbm.csv`) появляются только после успешного запуска `model.train`; прогнозы и метрики нельзя считать подтверждёнными до этого запуска.
