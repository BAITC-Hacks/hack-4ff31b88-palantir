## Данные и погода

Источники, правило «без утечки будущего», часовой пояс и очистка SCADA описаны в [data/README_data.md](data/README_data.md).

## Дашборд

```bash
python -m streamlit run app/dashboard.py
```

Откроется в браузере. Вкладки:
- **Прогноз** — почасовая мощность на 48 ч для выбранного выпуска и прогноз ветра ECMWF и GFS;
- **Проверки агента** — диапазон, скачки, расхождение погодных моделей, согласие с прошлым выпуском; журнал бэктеста агента (решение по каждому выпуску) и итоговый прогноз на февраль;
- **Качество модели** — nMAE на январе 2026 и график «факт против прогноза»;
- **Запуск агента** — полный цикл вживую: погода Open-Meteo на момент выпуска → признаки → модель → проверки. Выпуск в 12:00 UTC показывает пересчёт при обновлении прогноза погоды.

## Модель и метрики

Запуск модели: `python -m model.train`. Обучение идёт на `train.parquet` до
01.01.2026, январь 2026 используется для валидации, а февраль — для итогового
прогноза. Используются ветер и его ансамбль, направление в sin/cos,
температура, час, месяц и календарные циклы. Предсказание обрезается в [0, 1].

`nMAE = 100 * mean(abs(y - pred))`; результаты LightGBM записываются в
`model/metrics_lgbm.csv`, прогноз февраля — в `model/forecast_lgbm_feb.csv`.
После появления фактической SCADA скрипт также записывает сравнение LightGBM,
persistence, climatology и power curve за февраль в `model/metrics_february.csv`
с разбиением на горизонты 1–24 и 25–48 часов.

Метрики на январе 2026 (валидация, nMAE в % от установленной мощности, меньше — лучше):

| Модель | 1–24 ч | 25–48 ч | Все горизонты |
|---|---:|---:|---:|
| Persistence | 30.58% | 37.30% | 33.88% |
| Climatology | 29.26% | 29.14% | 29.20% |
| Power curve | 21.10% | 21.80% | 21.44% |
| **LightGBM** | **15.91%** | **16.97%** | **16.43%** |

Метрики считаются по фактической мощности `power`, время SCADA — UTC+6. В валидацию входят только выпуски после конца обучающих данных (с 01.01.2026 00:00 UTC), а кривая для поиска простоев строится без января. LightGBM обучается в несколько потоков, поэтому на другом компьютере его метрика может отличаться в сотых долях процента; значения в таблице — из `model/metrics_lgbm.csv` в репозитории.
Подробнее — в [разделе о данных](data/README_data.md). Пересчёт: `python -m model.baseline_nwp` и `python -m model.train`.

LightGBM снижает ошибку на 5 п.п. относительно кривой мощности по прогнозу ветра и почти вдвое относительно persistence.

## Агент: полный цикл за февраль

```bash
python agent_backtest.py --mode lightgbm --trained-through 2025-12-31T18:00:00+00:00 --out artifacts/agent_run
```

Агент «проигрывает» тестовый период: каждый день с 31.01 по 28.02.2026 в 00:00 UTC он сам выполняет цикл.
1. **Погода.** Берёт прогноз, известный на момент выпуска: `data.weather_client`, проверка `check_no_leakage`.
2. **Прогноз.** Готовит признаки и считает мощность LightGBM на 48 ч.
3. **Анализ.** Проверяет диапазон, пропуски, дубли часов, скачки и пересмотр относительно прошлого выпуска.
4. **Решение.** Принимает выпуск или отклоняет его. Принятый выпуск заменяет пересекающиеся 24 ч прошлого прогноза: так работает пересчёт при обновлении входных данных. Отклонённый пишется в журнал, а в силе остаётся прошлый прогноз.

Параметр `--trained-through` — момент, когда стало известно последнее наблюдение из обучения: 31.12.2025 23:00 по UTC+6, час закончился в 18:00 UTC. Если модель видела данные позже первого выпуска, агент откажется запускаться. Каждый запуск требует новую папку `--out`.

Готовый прогон уже лежит в репозитории, в `artifacts/agent_lgbm/`. Агент не перезаписывает прошлые эксперименты, поэтому для повторного запуска нужна новая папка, как `artifacts/agent_run` в команде выше. Состав результата:
- `february_latest.csv` — **итоговый почасовой прогноз на 1–28 февраля**: 672 ч, время SCADA UTC+6;
- `forecast_history.csv` — все версии прогноза по выпускам;
- `runs.jsonl` — решение агента, ошибки, предупреждения и резюме по каждому выпуску;
- `summary.json` — сводка прогона.

Проверка: 29 из 29 выпусков приняты, 672 из 672 часов февраля. Прогноз агента совпадает с `model/forecast_lgbm_feb.csv` до последнего знака.

**LLM-резюме (необязательно).** Нужно выполнить `pip install openai`, задать переменную окружения `OPENAI_API_KEY` и добавить `--llm-model <модель>`. Без ключа или при ошибке API резюме строится по правилам.

**Другие режимы и тесты.** Бейзлайн запускается с `--mode baseline`. Тесты агента: `python -m unittest discover -s tests -v`, их 19. Подробности — в [docs/agent_integration.md](docs/agent_integration.md).

## API-сервис агента

Тот же агент как веб-сервис: его можно вызывать из других систем (диспетчерская, торговая платформа) или запускать по расписанию.

```bash
python -m uvicorn api.main:app --port 8000
```

Откройте **http://localhost:8000/docs**: это Swagger, в нём каждый эндпоинт можно вызвать из браузера кнопкой «Try it out».

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/forecast/run` | полный цикл агента на момент выпуска: погода Open-Meteo, известная к этому моменту → признаки → LightGBM → проверки → резюме → решение. Пустой `issue_time` — прогноз «на сейчас» (ближайший прошедший срок 00/06/12/18 UTC) |
| GET | `/forecast/latest` | актуальный прогноз на 48 ч от самого свежего принятого выпуска; `?source=backtest` — итог февраля (672 ч) |
| GET | `/forecast/{issue_time}` | выпуск целиком: 48 ч, ошибки, предупреждения, резюме |
| GET | `/runs` | журнал решений агента (выпуски через API и бэктест) |
| GET | `/health` | состояние: модель, LLM, расписание, число выпусков |

Мощность в ответах — доля от установленной (`power_pred`, 0…1) и проценты (`power_pct`); `target_time_local` — время SCADA (UTC+6). Состояние хранится в `api/state.sqlite`. Принятый выпуск заменяет пересекающиеся часы прошлого прогноза, отклонённый пишется в журнал с причиной.

Настройки — через переменные окружения:
- `AGENT_SCHEDULE_HOURS=6` — агент **сам** делает выпуск каждые 6 часов, без участия человека;
- `LLM_MODEL=gpt-4o-mini` вместе с `OPENAI_API_KEY` — резюме от LLM;
- `AGENT_MODEL=baseline` — кривая мощности вместо LightGBM.

Публикация: `docker build -t wind-agent . && docker run -p 8000:8000 wind-agent`. Тот же `Dockerfile` подходит для Render, Railway или Hugging Face Spaces; ключ OpenAI задаётся там в секретах, а не в коде.

## Воспроизведение с нуля

Нужен Python 3.10+. Исходные CSV организаторов уже лежат в `data/raw/`.

На Windows, если команда `python` открывает Microsoft Store или не находится, используйте лаунчер `py` вместо `python` (например, `py -m pip install -r requirements.txt`). На Linux и macOS может понадобиться `python3`.

```bash
python -m pip install -r requirements.txt
python -m data.build_dataset       # архив прогнозов Open-Meteo + SCADA -> data/processed/
python -m model.baseline_nwp       # бейзлайны и метрики на январе
python -m model.train              # LightGBM: метрики на январе, прогноз на февраль
python agent_backtest.py --mode lightgbm --trained-through 2025-12-31T18:00:00+00:00 --out artifacts/agent_run
python -m streamlit run app/dashboard.py
```

Февральские метрики считаются по целевым часам 01.02–28.02 (`target_time_local`). Фактической мощности за февраль в выданных данных нет, поэтому `model/metrics_february.csv` заполнится, когда эти данные появятся в `data/raw/`.
